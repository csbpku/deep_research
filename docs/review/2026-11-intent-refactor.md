# 意图驱动的研究产物：第一轮重构

日期：2026-11-16
分支：`codex/product-funnel-fixes`（PR #56）

## 结论

现有 `RESEARCH_OBJECTIVE`（explore / learn / investigate / decide）不再只是计划文案，
而是会决定引擎的报告契约；确认页也会按意图选择默认产物。

第一轮只做“意图 → 契约 → 默认产物”，不重做检索链路，也不引入新的报告类型。

## 改了什么

1. **意图进入引擎请求**
   - `JobSnapshot` / `ResearchRequest` 增加 `objective`；
   - `db_store.py` 的 snapshot SQL 读取 `ai_research_jobs.objective`；
   - `runner.py` 把 objective 传进适配器。

2. **意图决定报告结构**
   - `gpt_researcher._intent_report_contract()`：
     - `learn`：一句话回答 / 心智模型 / 分层解释 / 可运行示例 / 边界与误区 / 自检 / 一手来源；
     - `investigate`：现象与范围 / 竞争假设 / 证据 / 判别性证据 / 结论与置信度 / 剩余不确定性；
     - `explore`：一句话概览 / 主题地图 / 关键问题 / 主要方向与分歧 / 证据缺口 / 下一步阅读；
     - `decide`：沿用已有对比/决策契约。
   - 已确认的意图优先于关键词比较启发式；用户在计划里选了 `learn`，不会因为上下文出现“取舍/对比”就被改写成选型报告。
   - 没有显式 objective 的旧调用保持原契约，避免影响历史测试和旧任务。

3. **默认产物由意图决定**
   - 确认页在用户未手动改过产物时：
     - `decide` → 决策备忘；
     - `learn` / `investigate` / `explore` → 完整报告。
   - 用户手动选择后不再被覆盖。

4. **详情页显示研究意图**
   - `/api/researches/[id]` 返回 `researchObjective`；
   - 详情页新增「系统学习 / 机制分析 / 主题概览 / 决策对比」徽章。

## 覆盖检查

学习与机制分析契约的末尾都要求一个 `## 覆盖检查` 表格：逐行列出计划中的必答问题，
标记“有证据 / 未知 / 冲突”。真实学习任务 `30c2d00e…` 的草稿
`47bbb255-0a9b-5899-9fb8-a933b8a7b801` 已生成该表，三行均为“有证据”，并带 [S#]。

局限与修正：首版把完成标准也并进了同一张表，标成“有证据”。现行契约要求
表格只放必答问题，完成标准另起一行标“已满足/未满足”；重跑草稿
`b5111bd9-7e41-5851-a157-d8028ccd668f` 已按此输出。

行内引用也改成紧凑 `[S#]`：学习/机制/概览三类产物不再把来源标题铺进正文，
完整链接只出现在文末参考来源。修复了一个幂等性 bug——writer 自带
`[S1](url)` 时不再被二次展开成 `[S1](url)(url)`。

## 发布门禁

`parseIntCoverage` 的输出现在同时用于发布：只要存在 `unknown` 或 `conflict`，
`POST /api/researches/[id]/publish` 在没有 `acknowledgeDisclosure` 时返回 400
`必答问题里仍有未知或冲突项；确认披露后才能继续发布`，并在 `details.intentCoverage`
里返回完整表格。编辑弹窗同步显示未知/冲突计数，勾选同一条披露后才允许发布。

实测：给 `b5111bd9…` 的覆盖表临时加入一条“未知”，不带确认调用发布返回 400；
`details.intentCoverage.counts` 与实际行一致。`partial` 仍只展示，不强制确认，
因为它是“有证据但有限定”，不是未覆盖。

## 仍未做

- 覆盖状态没有进入已发布版本的快照（已在后续提交补上）；
- 还没有独立的学习路径渲染器（目前是 Markdown 契约，不是交互式路径）；
- 对比意图仍复用 `decide`，没有“只对比不推荐”的开关；
- 学习产物仍偏长，尚未按投入档位限制篇幅。

## 覆盖快照

`Research.publishedIntentCoverage` 在发布时写入当时的解析结果（迁移
`20261116000003_published_intent_coverage`）。读者页优先用它，并标注
“发布时确认的覆盖状态”，而不是重新解析当前正文。

实测：发布 `b5111bd9…` 后快照计数为 `evidence 1 / partial 3`；随后在正文里临时
插入一条“未知”，详情 API 仍返回同一份快照（`intentCoverageSnapshot=true`），
读者不会看到发布后才出现的覆盖变化。测试后已还原正文。

## 对比矩阵

新增产物 `comparison_matrix`（UI「对比矩阵」），用于“只对比，不推荐”的场景。
它复用同一套证据和覆盖检查，但输出契约不同：

- `## 对比结论` 只给条件性结论，禁止唯一推荐；
- `## 对比矩阵` 每格一条结论 + `[S#]`，未知/冲突必须显式；
- `## 权重敏感性` 至少给出两组前提；
- `## 适用条件`、`## 未知与冲突`、`## 下一步验证`。

真实任务 `0bc02344…` / `78d41e8e…`（库存扣减：advisory lock vs `FOR UPDATE`）：
17,717 字 → 13,364 字；矩阵每格一句、引用紧凑为 `[S1]`；全文 0 处
“推荐方案/建议选择”；审核 `needs_revision`、outcome `attention`。

## 矩阵单元格门禁

对比矩阵发布前逐格检查：每个非首列单元格必须包含 `[S#]`，或显式写明
“未知/待实测/未确认/冲突/未找到/无直接证据”。缺一项即返回 400，并在
`details.comparison.unmarked` 列出具体行列。

实测：给 `ac3946c3…` 临时加一行无引用的“测试方案”，发布返回
`400 对比矩阵有 5 个单元格既没有证据编号，也没有标为未知或冲突`；
恢复正文后字数回到 13,364。解析器 3 例单测，发布路由 35 例通过。

## 学习路径

`learning_path` 不再复用长报告：六个固定章节，目标 2,400 字，硬上限 3,200。
`ai_engine/learning_path.py` 按节削到预算，保留全部标题；引用使用 `[S#]`。

真实任务 `6538e0d1…` 草稿 `2bc95817…`：2,784 字，六节齐全，概念图是表格，
概念句带 `[S1]`，390px 无横向溢出；审核 `needs_revision` / `attention`。

## 学习路径结构门禁

概念图区不再按字符截断（曾把 6 个概念截成 2 个）。现在表格整块保留，
按 4–6 行裁剪；发布前 `checkLearningPath` 校验概念数 4–6、每行关系列非空，
缺失返回 400 `学习路径的结构还不完整：…`。

真实验证：把 `8e442126…` 的“事务快照”关系改成 `-`，发布返回
`400 学习路径的结构还不完整：概念「事务快照」缺少与其他概念的关系`；
恢复后仅剩披露门禁。全量 web 1529 passed / 16 skipped，python 1793 passed。

## 学习自检交互

学习路径的 `## 自检` 不再直接摊开答案。读者先看到问题与“先想一想，再显示答案要点”，
点击后才展开该题的答案，其他题仍保持隐藏。

- `apps/web/src/lib/research-self-check.ts` 解析编号问题、行内“答案要点：”与下一行答案；
- 答案里的 Markdown 引用压成 `[S#]`，不再显示完整 URL；
- 正文渲染时移除自检段，由 `LearningSelfCheck` 组件接管，避免答案重复出现；
- 非学习路径不渲染该组件。

真实验证：`8e442126…` 在 390px 下出现 2 个“先想一想”按钮，点击第一条后答案展开，
控制台无报错，`scrollWidth - clientWidth = 0`。

### 自评闭环

自检题现在先让读者选“会 / 不确定 / 不会”，再展开答案，并显示自己的自评。
选择写入 `localStorage` key `deep-research.self-check.v1`，刷新后保留；同题再次
进入时直接显示上次自评与答案。正文渲染改用 `stripSelfCheckSection` 精确移除
`## 自检` 段，避免答案在正文与组件里重复出现。

### 复习队列

自评结果按研究 id 分开存储（`deep-research.self-check.v1.<researchId>`），
避免不同文章的题目互相串。标为“不确定/不会”的题会在组件顶部汇总：
“还有 N 道题需要复习”。刷新后自评与已展开的答案一起恢复，读者能直接
回到上次的薄弱点。

### 账号级自评

自评现在同时写本地与 `learning_self_check` 表，按 `(userId, researchId, questionKey)`
唯一；页面加载先读本地缓存，再以服务端结果覆盖，换设备/换浏览器也能恢复。
接口 `GET/POST /api/learning/self-check` 只返回当前用户自己的评分。
迁移 `20261117000002_learning_self_check` 已在本地应用。

### 待复习筛选

研究库新增“只看待复习”复选框，走 `GET /api/researches?needsReview=true`。
`researchListWhere` 只保留当前用户在该文章下有 `unsure`/`missed` 自评的记录，
按文章聚合，不展开到题目。draft 视图下实测命中 1 篇（MVCC 学习稿），
列表数从 20 降到 1，`scrollWidth - clientWidth = 0`。

### 复习优先级

“只看待复习”不再只按最新排序：`rankResearchForReview` 先看 `missed` 数量，
再看 `unsure`，最后看最老一条自评的时间。卡片显示“N 题未掌握 · M 题待确认”。
排序在服务端做，只取当前页不够，后续若文章数量上来需要改成游标分页。

### 全库复习排序

“只看待复习”不再只排当前页：接口先按当前用户聚合 `learning_self_check`
（`missed` / `unsure` 计数、最老自评时间），对全部候选文章排序后再切页，
最后按 id 回表取详情。分页总数是排序后的总数，不是当前页长度。

实测造 25 篇同作者草稿、各 1 条 `missed`，把 MVCC 稿的自评时间改到 10 天前：
它从第 2 页升到第 1 页首位，`total` 26。测试数据已删除。

### 概念关系可读性

概念图仍允许“包含 xmin/xmax 与活跃事务列表”这类解释性关系，
但挡掉纯占位符号（`-`、`—`、`/`）和“相关/有关/不适用”这类空话，
以及把“含义”列原样抄进“关系”列。发布门禁给出具体概念名，
而不是笼统地说“结构不完整”。

### 学习路径的发布摘要

学习路径有自己的摘要结构（90 秒回答、概念图、误区、自检），发布时不再要求
研究稿的“背景/结论/风险”三件套。此前真实学习稿 `8e442126…` 正文 2,989 字、
摘要三字段全空，编辑页直接禁用发布；现在只要求正文非空。

真实发布：`acknowledgeDisclosure=true` + 当前 `publicationVersion` → 200
`status=published`。

### 发布摘要规则收敛

研究稿要“背景/结论/风险”，知识卡片和学习路径只要正文。这条规则此前在
`publish/route.ts` 和 `edit/page.tsx` 各写一遍，新增学习路径时只改了 API 的
第一段，编辑页仍按研究稿判断，导致按钮禁用。

现在两处都调用 `publicationSummaryRequirement()`，返回 `kind / required /
missing / missingLabels / complete`；新增类型只改这一个函数。测试覆盖研究稿、
知识卡片、学习路径、AI 研究稿四种组合。

### 待复习列表的候选集

`needsReview` 以前先 `research.findMany({ where })` 拉全部匹配文章，再在内存里
排序切页。实际上只有存在当前用户 `unsure/missed` 自评的文章才可能进入结果，
所以先 groupBy 自评，再用这些 `researchId` 作为候选集；空集合直接返回 0。

这把候选集从“整个研究库”降到“用户实际评过的文章”，分页语义和排序规则不变。
