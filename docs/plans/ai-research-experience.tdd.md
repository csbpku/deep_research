# AI 调研优化技术设计与测试设计（TDD）

来源：[优化方案](./ai-research-experience.plan.md)。技术设计和测试先行共同约束实施。

## 模块与契约

### Web 方案与草稿

- 将纯 UI 研究确认控件拆入独立组件；父会话仍拥有产物、深度、来源和提交状态。研究方案只拥有可编辑研究目标/问题/对比对象/范围等内容，通过现有 BriefValue 合成提交值。
- 草稿存储提供版本号、账户 ID、会话 ID、可验证字段和恢复保护；本地状态不覆盖已提交任务配置，也不能跨账户泄漏。计划初次恢复和后续请求有明确先后次序；对已编辑字段不采用晚到的自动值。
- 回执以 job reportType/reportLength/sourcePolicy/sourceRefs/brief 为权威。未加载/未知值不可用默认选择冒充。
- 错误恢复按原操作分类；校验不触发提交，保存失败不触发研究。若提交结果不确定，先查询任务历史，不盲目创建另一个任务。

### 证据与版本

- sourceRef/canonicalKey/citation identity 不变；重用既有 JSON partialSources 保留有界正文，短列级 snippet/description 仍为预览。writer 引用的证据应可由持久快照回查，review 使用同一内容。保持现有 SSRF、超时、最大正文和总 token 预算。
- 自动研究 review revisionHash 统一使用与 Web 相同的 title/body/background/conclusion/risks/tags 完整快照算法，originContentSha256 仍为正文 SHA-256。旧版本审核不自动匹配当前研究。
- 零可用来源在最终来源修复/抓取完成后、写作前停止，并将错误归属检索阶段。evidence_search 等内部任务原有错误契约保持。

### 规划语义与视觉

- objective 枚举保持 explore/learn/investigate/decide，文案区分目标与投入。对比对象提取必须去除任务指令、场景描述，未知时返回待确认。
- decisionDimensions 优先使用显式方案，其次从问题选择相关维度；不把默认通用维度写成用户明确要求。跨运行时 schema 镜像保持兼容。
- 单选控件有组名、名称、状态与键盘交互；主按钮与已选项视觉区分。颜色来自共享 light/dark tokens。正文对比度4.5:1，必要图标/控件3:1。

## 回归测试与验收矩阵

| 用户保证 | 自动化层 | RED 触发 | GREEN 验收 |
|---|---|---|---|
| 刷新后产物、深度、来源和编辑方案保持 | 单元/API/浏览器 | 复现丢失及异步覆盖 | 同账户同浏览器恢复，换账户隔离，坏存储可恢复 |
| 回执如实显示已提交配置 | 组件/浏览器 | 单轮任务恢复为多轮 | 等待真实配置，失败不冒充默认 |
| 保存失败重试不会创建研究 | 单元/浏览器 | 保存错误重试触发submit | 只执行保存/展示相应恢复 |
| 比较对象不含场景/输出要求 | API单元 | Playwright/Cypress中文真实问题 | 精确两项；模糊输入请求确认 |
| 研究维度与问题相符 | 单元/契约 | asyncio比较产生磁盘回滚 | 仅相关默认/显式维度，运维比较保留严格要求 |
| 指定长文后部事实进入写作与可核对证据 | Python单元/集成 | 前1000为导航、答案在后文 | 同一有界正文保留、锁定来源不调用搜索 |
| 新报告审核为当前版本 | Python/TS契约 | body-only hash与完整快照不同 | 同值同hash，修改正文/标题后失配 |
| 零来源不进入无证据写作 | Python单元 | writer被调用/错误归属write | writer未调用、search失败、有源路径不变 |
| 追问引用无协议标记外露 | 单元/浏览器 | 展示[[cite]]标签 | 引文保留，完整/残缺标记不外露，不伪造引用 |
| 7–29天不显示0个月前 | 单元 | 边界时间 | 正确天数/周/月，未来和无效值安全 |
| 选项分组、单选和主操作清晰 | 组件/浏览器 | 旧布局缺少角色/摘要 | 等尺寸产物、统一选中、明确分组与摘要 |
| 手机和键盘路径可用 | Playwright/真实浏览器 | 320/390首屏裁切 | 320/390/768/1024/1440无文本裁切；Tab、Space、方向键、Esc与焦点恢复 |

## 验证与证据

- 按工作流记录实际 RED/GREEN 命令、失败原因、checkpoint 提交与通过数；在完成前不填造通过状态。
- Web：Vitest相关回归、pnpm typecheck、全部现有单测、Playwright行为回归；不以纯渲染静态快照判定响应式通过。
- Python：pytest相关回归和全量测试，Ruff、mypy。
- 设计系统：token生成与 --check、主题测试、明暗模式关键对比度。
- 浏览器：新增实现的开题->确认->启动->进度->结果->追问与刷新；使用隔离真实服务和标记测试，允许既有授权的真实 LLM 调用。失败时调查并复测，不以首次失败为验收结束。
- 全部结果汇总至 PR 和本地忽略的验收记录；部署状态单独报告。
