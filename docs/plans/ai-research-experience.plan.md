# AI 调研体验优化方案

## 现状与目标

现有 AI 调研是对话开题、确认方案、异步研究、私有产物和继续追问的 Operate/Read 工作台。视觉沿用共享 MUI/Emotion 主题；本次是现有系统优化。真实走查复现了配置恢复错误、手机首屏裁切、资料过早截断、审核版本计算不一致、零来源失败阶段误导、比较对象误识别、固定检查维度和引用标记外露。

目标是用户能明确决定研究问题、产物、投入和资料，并在刷新、失败和完成后准确理解发生了什么。使用者是平台中的技术研究者和需要核验证据的决策者。产物仍是研究稿、网页简报、Slides 提纲、快速判断；快速判断保留非正式研究稿的限制。

## 实施方案

1. **方案结构**：以“研究什么 / 交付什么 / 投入多少 / 参考什么 / 确认启动”组织。研究目标为辅助设置，区分目标、研究投入和产物；调整容易混淆的目标文案，保持枚举与已有任务兼容。产物四选一、深度二选一、资料策略二选一采用一致的单选语义。组内紧凑、组间留白；深色实心只用于主要操作，选择以浅底、边框和可访问的选中标识表达。低相关历史候选按需展开，已选资料可见。简明摘要与提交操作保留在方案上下文。
2. **色彩与响应式**：保留蓝色操作/选择，证据资料改用独立青色语义 token；成功、待确认、错误沿用绿/琥珀/红。使用共享 tokens，生成 CSS，不维护独立色值。白色内容区、安静中性背景，消除无意义的多层框与大块说明底色。修复首屏 intrinsic width、长示例和消息的裁切；验证五个尺寸和键盘。
3. **配置与恢复**：未启动配置按账户和会话隔离保存在浏览器，包含来源、产物、投入、方案编辑和草稿；明确保存范围，不承诺跨设备同步。存储禁用/损坏可恢复，异步计划不能覆盖用户编辑。已启动任务回执从服务端 job 配置构建，读取失败显示无法确认/重试。区分保存、提交和输入错误的恢复动作，防止保存重试意外启动任务。
4. **证据与审核**：指定 URL 的真实正文在既有 JSON 快照和预算内保留，给写手、持久化与审核的可核对内容一致；列级短预览保留。不得以网页目录代替全文，也不得只把私有长上下文给写手。统一自动审核和 Web 的完整 revision hash，保留原正文 origin hash 语义。无有效来源在写作前明确失败，不虚构后续成功阶段。
5. **规划与输出**：比较对象只提取可靠命名对象，场景和“给出建议”等要求不作为候选；不可靠时请确认。检查维度来自问题/已确认方案，避免任意比较都被强加部署、磁盘和回滚。保留用户明确要求这些维度时的证据门禁。清理显示层引用协议标记并保留原文和引用边界；统一相对时间边界。

## 边界与交付

- 不修改 Prisma schema/迁移，不回填或重新评判历史生产任务。
- 不修改已有真实内容，不自动合并或部署；完成代码、测试、真实浏览器验收、分支推送和 PR。发布仍按仓库授权边界执行。
- 保留原工作树与已有报告。所有新测试数据使用隔离环境/可辨识标记；内部验收证据在本地忽略目录中保留。
- 用户已选择不启用 VoiceOver。检查键盘及无障碍树，不声称完成屏幕阅读器播报验证。

## 顺序与验收

完成本方案与配套 TDD 技术设计后，按独立工作流先添加回归测试并实际运行至 RED，保留 checkpoint；再实现 GREEN，最后集成与浏览器验收。测试必须证明用户行为，不以源码字符串或快照镜像替代行为。具体验收矩阵见 ai-research-experience.tdd.md。

## Slides 补充优化

真实生成暴露出深色舞台中的正文颜色未随表面反转、长引用挤占要点、固定画布里再次滚动、全局翻页监听影响其他输入等问题。Slides 保持平台主题，改为简洁的演示页面：以标题和三条以内的要点为主体，引用折叠为编号和独立来源区，去除装饰圆线与英文标签；演示与完整提纲各有明确用途。手机使用自适应高度，桌面保留演示比例；键盘翻页限定在预览内。用户明确指定页数时，生成契约包含封面和收尾页的总页数，参考文献不额外算作一页。
