# 每条雷达的质量检查清单

雷达的基本单位是一篇有确定出版身份的内容，不是一个仓库、一个标题或一个 URL 下的所有历史内容。保留价值、能否可靠评分、是否适合公开展示分别判断。缺分、旧内容、来源失败均不直接构成噪声或删除依据。

已有有效噪声评分的条目进入独立处置清单，不再运行摘要、判断补齐或计入内容完整性统计。按库主持续授权，当前有效噪声评分且无引用保护的自动雷达物理删除，不再要求原文完整可抓取或有逐字引文；旧版/无效评分和有保护关系的内容保留并说明原因。排除统计本身不构成删除资格。

当前阅读等级统一为精读（`deep_read`）、速读（`skim`）、噪声（`noise`），原收藏级并入精读；用户收藏仍是独立操作。新评分采用 Distilled 5.1。已有有效分数及其版本保留，阅读迁移不隐式重评分；显式 Admin 迁移按[统一评分治理](./radar-governance.md#unified-external-reading-and-scoring-51)核验站外阅读路径，只有单独选定的旧噪声允许按当前标准复核。

## 必需内容与条件

| 项目 | 每条应具备的内容 | 检查与例外 |
|---|---|---|
| 身份与来源 | 唯一 ID、真实标题、原文 URL、规范 URL、入库来源与时间 | 自动雷达须能关联真实同步批次/来源；用户分享须审核通过。URL 格式合格不等于当前可达。 |
| 摘要 | 说明“是什么、做什么、如何做、有什么限制”的可用摘要 | 禁止标题复读、失败提示及占位文字。当前自动补救的结构底线为 80 字符；达到长度仍须语义核验。 |
| 判断 | 具体适用场景、价值与限制 | 当前结构底线为 30 字符；不得把未经验证的模型推断当事实。 |
| 有效评分 | 非默认、非全零、七维 0–3 评分，合法总分、等级、版本和 profile | 有效旧版评分保留，不为升级版本而重评。证据不足时允许暂缺，必须明确未解决。 |
| 展示一致性 | 展示分数对应 tierScore（旧格式无该值时使用 total），目标层级对应评分 | 旧站内正文尚未就绪时，实际层级可以降为 skim；这不是评分矛盾。 |
| 判断证据 | 可读评分理由、来源/证据身份、可复核的审计 | 缺引文的有效旧评分进入证据复核，不直接作废。hash 只能确认文本身份，不能证明判断正确。 |
| 阅读入口 | 明确走原文阅读或站内阅读 | external_reading 只要求有效原文入口，不要求缓存正文或旧审核通过；高价值站内阅读需来源完整性、enrichment、reader 质量和内容审核通过。render 审核为可选，不人为增加公开门槛。 |
| 状态真实 | 当前状态、公开资格、展示阻塞与实际证据相符 | 噪声/未评分不公开；新同步确认噪声后不入库，存量按治理契约删除并保留库外恢复归档。归档/屏蔽不要求重新公开。 |
| 引用保护 | 用户笔记、分享、收藏、批注、研究/聊天/专题引用及手动 pin 可追踪 | 检查保护关系；任何删除前仍须在事务内重新检查，不能凭旧清单直接删除。 |
| 失败与重试 | 每个已尝试失败都有明确原因、次数、下一次时间或终止原因 | 未轮到的待办明确标“尚未尝试”；退避/次数上限见治理契约，禁止无条件重试。 |
| 诊断一致 | 当前待办对应仍存在的问题、同 run/URL 已解决项不继续待处理 | 同 URL 不同 run/证据不互相替代；重复待办按来源/URL/原因/种类/证据识别。 |
| 完整性与重复候选 | 有缓存时核对字节数/hash；疑似重复有单独候选清单 | 外部阅读无缓存为不适用；相同标题、同仓库不同文章仅提示核验，不自动合并。 |

## 结果含义

- `passed`：本检查覆盖的结构/关系规则通过；不代表语义质量审核通过。
- `missing`：适用的必需内容缺失，或队列尚未尝试；须保留具体原因。
- `invalid`：已有字段与契约或证据矛盾。
- `not_applicable`：此模式不要求该项，例如外部阅读不要求正文缓存。
- `unverified`：需要读原文、人工判断或重新采样才能确认，包括并发中的断点。

“基本齐全”仅指身份、来源、摘要、判断、评分、评分展示一致性六项结构检查通过。当前可达性、来源身份与语义忠实度须单独验证，不能将“基本齐全”写成“质量合格”。旧缓存异常或缺评分理由也会单独列出。

公开自动雷达使用同一有效评分门槛：七个已知维度均为 0–3 整数且非全零、非默认评分、总分在 0–100、profile 与版本格式有效，评分等级与展示等级一致；保留旧站内高价值降为 skim 的兼容规则。合法旧版评分继续有效，不要求升级版本或重新评分。详情、列表分页与总数、搜索、专题和调研来源回查均执行此门槛；已批准分享沿用分享规则，Admin 显式治理队列仍可读取缺分或无效评分。专题在读取既有候选、热点证据与趋势时重新核对资格，候选在过滤后才取前 50 条；无合格证据的热点不进入详情响应。读取检查不删除历史关联或引用。跨运行时共享用例及 PostgreSQL 只读测试校验判定一致。

## 只读逐条执行

身份检查拒绝仅为 `Skip to main content` 或 `Skip to content` 的导航标签；正常文章标题中提及这些词仍有效。厂商新闻的标题提取和文本回退使用同一规则，旧记录须按原文核实后纠正，不据此删除或重新评分。

评分理由可来自 `weakPoint`、`relevanceEvidence`、`scopeEvidence` 或旧 `scoreReason` 的非空文本。存在理由只记为待核验，不表示引文、原文可达性或评分语义已验证。

在 AI-engine 包目录（生产 `/app`）运行：

```sh
python -m scripts.audit_radar_quality \
  --actor <真实Admin邮箱或ID> \
  --output <新的私有证据目录> \
  --repair-state <持久repair目录>/state.json
```

盘点范围为所有自动雷达及已批准分享，含拒绝/归档项；未批准的分享投稿不算雷达。有效评分噪声单列为处置对象，其余逐条做完整性检查；不按活跃状态或年龄排除。程序使用单个 `REPEATABLE READ, READ ONLY` 事务，核对范围行数＝质量检查行数＋噪声处置行数，并核对唯一 ID；不抓取原文、不调用模型、不触发同步、不写业务库。断点在事务前后读取且逐行核对版本；并发变化标待验证。

输出 `summary.json`、质量范围逐条 `all-radar-checks.csv/json`、独立 `noise-disposition.json`、问题明细 `issues.csv`、同快照待办证据 `pending-diagnostics.json`、SQL 与 SHA-256 manifest。逐条输出包含 ID、状态、来源、时间、各项结果、证据、保护原因和下一步动作。真实数据产物只存私有证据目录，不提交公开 Git。

该 CLI 当前会加载完整行。生产内存受限时，不在业务 AI 容器运行全库版本或旧 `report.py`；本轮采用只传数据库凭据、正文逐条游标读取的 512MiB 独立只读维护容器。固定快照与执行脚本见 [本轮逐条复核证据](../weekly/2026-10-15-radar-governance-full/SCORE_GATE.md)。持续进度使用不加载正文或审计大字段的 `report-lite.py`；流式执行方式尚待并入正式 CLI。

治理写入、模型预算、条件删除和恢复依然服从 [治理契约](./radar-governance.md)。本清单不产生删除、重评分、审核通过或公开内容的授权。
