### 本轮新增问题

#### P1：知识卡片提炼失败后缺少就地恢复动作

在雷达详情打开“提炼为知识卡片”后，真实 AI 调用最终显示“AI 调研服务暂时不可用”。错误文案能被看到，但没有明确的“重试”按钮，也没有说明是暂时失败、额度问题还是服务未启动。

建议：

- 失败区域提供“重试提炼”和“关闭预览”两个动作。
- 保留原引用内容，不要求用户重新选区。
- 对服务不可用、内容提炼失败、权限不足使用不同的用户语言。
- 失败状态使用 `role="alert"`，并让焦点落到错误区域或重试按钮。

#### P1：功能覆盖中存在“打开但未完成”的危险误读

部分运营功能的 UI 能打开，不代表端到端行为已被验证，例如主题发布、成员禁用、导入文件、知识卡片保存和真实 AI 调研启动。后续验收报告应明确区分：

- 页面可达。
- 控件可操作。
- 请求成功并反馈。
- 数据变化可回读。
- 失败后可恢复。

这五层不应合并为一个“功能正常”结论。

#### P1：Admin 主题提议队列的信息密度仍然过高

主题提议页一次呈现大量提议卡片，每张都包含主题名称、共同命题、多个证据、来源链接和审核动作。真实打开后，审核者需要长距离滚动才能在提议之间比较。

建议：

- 默认只显示主题名称、置信度、证据数量和发布方数量。
- 证据列表折叠，点击后展开。
- 增加“待审核 / 高置信度 / 证据不足 / 已选中”筛选。
- 将驳回和发布动作固定在当前提议的局部操作栏，减少误点。

#### P1：雷达正文里的 AI 处理状态需要更明确的生命周期

AI 讨论实际经历了“正在读取原文和摘要 → 正在生成回答 → 回答与引用出现”的过程，反馈是有的；但生成完成后仍可能短暂保留“停止生成”语义，用户不容易判断是否还在继续输出。

建议：

- 生成完成后立即切换为“重新生成”或移除停止按钮。
- 显示“已生成，引用 3 段”之类的完成状态。
- 生成失败时保留原问题，并提供重试。

## 本轮新增发现

### P0：AI 调研结果页存在多层嵌套滚动

移动端结果页检测到多个独立滚动区域：

- 主页面高度约 `2676px`。
- 产物 tabs 内容宽 `478px`，容器宽 `295px`。
- “一页判断”卡片内容高 `1071px`，容器高 `398px`。
- 继续追问区域内容高 `626px`，容器高 `420px`。
- 最近对话区域内容高 `599px`，容器高 `221px`。

真实截图中已经出现报告卡片内部滚动条。用户需要在页面滚动、报告卡片滚动、对话区域滚动之间反复切换，容易错过内容，也会增加触控操作成本。

建议：

- 移动端报告正文自然展开，取消正文卡片固定高度和内部滚动。
- 继续追问改成折叠面板或底部 sticky action，默认不抢占正文首屏。
- 最近对话和研究详情默认只显示摘要，点击后再展开。
- tabs 保留横向滚动，但强化当前 tab 和“还有更多内容”的可发现性。

| 控件 | 实测尺寸或高度 |

### P1：Admin 用量表格的横向滚动不够可发现

Admin LLM 用量页没有根页面横向溢出，但内部表格存在宽内容：

- 第一张表约 `821px`。
- 明细表约 `1023px`。

功能本身可用，但移动端用户不一定知道表格可以左右拖动。

建议：

- 表格容器两侧增加轻微渐隐或滚动阴影。
- 首次进入时显示一次“左右滑动查看明细”的短提示。
- 固定关键首列，例如时间、任务或模型。
- 移动端默认隐藏低价值字段，提供“查看完整明细”。

### P1：路由级错误恢复边界覆盖不足

当前发现的加载边界主要是：

- `apps/web/src/app/loading.tsx`
- `apps/web/src/app/radar/[id]/loading.tsx`
- `apps/web/src/app/topics/[slug]/loading.tsx`

没有发现对应的 `error.tsx` 路由边界。skill 的 Next.js 查询明确建议使用 `error.tsx` 和 `reset` 恢复动作。考虑到旧开发服务曾出现 chunk/client-side exception，这一项值得补齐，即使生产环境目前多数路径正常。

建议优先覆盖：

- `apps/web/src/app/ai-research/error.tsx`
- `apps/web/src/app/researches/error.tsx`
- `apps/web/src/app/search/error.tsx`
- `apps/web/src/app/admin/error.tsx`

错误 UI 至少应包含：

- 用户能理解的错误原因。
- “重试”按钮。
- 返回上一级或回到工作台的动作。
- `role="alert"` 或等效可访问播报。

### P1：异步状态和反馈仍需统一

本轮验证到加载态、完成态、证据整理和后续追问均可工作，但 AI 调研结果页仍容易同时呈现“已完成”“需要确认”“依据需要重新整理”等多个状态。用户不容易快速判断报告能否直接使用，以及下一步应该点击什么。

建议定义三层状态：

1. 执行状态：排队、研究中、已完成、失败。
2. 质量状态：可直接参考、需要确认、资料不足。
3. 用户动作：唯一主 CTA，例如“重新核对当前版本”。

同一屏只保留一个主状态和一个主 CTA，其余状态降级为说明或质量检查详情。

## 保留并继续强化的优点

- 研究工具采用高信息密度布局，没有营销式大 Hero，适合持续工作场景。
- 雷达、专题、研究库、AI 调研和 Admin 的导航层级已经形成产品骨架。
- 真实移动端批量走查未发现根页面横向溢出。
- 现有代码中已经有不少 `aria-label`、`aria-live`、`role="status"`、`focus-visible`、TooltipProvider 和 loading UI。
- AI 调研结果、证据地图、雷达阅读和 Admin 用量都具备真实数据和可继续操作的闭环。

因此下一轮重点应是交互尺度、状态语义和恢复路径，不需要先做大规模视觉换肤。

## 改进计划

### 第 1 阶段：移动端阅读和触控

- AI 调研结果移动端正文取消内部滚动。
- 继续追问、最近对话和研究详情改为渐进披露。
- 统一 icon button 的 `44×44px` 触控热区和 `8px` 间距。
- 保留视觉密度，优先扩大可点击区域而不是放大所有图标。

### 第 2 阶段：错误、加载和反馈

- 为 AI 调研、研究库、搜索和 Admin 增加路由级 `error.tsx`。
- 为重试、刷新、归档、收藏、发布和保存统一成功 / 失败反馈。
- 把 AI 调研状态收敛为“执行状态 + 质量状态 + 唯一主 CTA”。
- 为长时间异步操作保留稳定布局，并播报进行中状态。

### 第 3 阶段：表格和长内容可发现性

- Admin 表格增加横向滚动提示、固定关键列和移动端字段优先级。
- 研究正文、证据地图和雷达原文继续遵循自然阅读优先。
- 对长标题、URL、模型名和内部 operation 名称做换行和用户语言映射。

### 第 4 阶段：验收自动化

- 固化 `375 / 390 / 768 / 1024 / 1440` 五档视觉回归。

### 状态定义

- `✅`：页面、主要控件、关键反馈和至少一个真实结果状态已看到；没有明显的 UI/UX 阻塞。
- `🟡`：页面和主要控件已走查，但成功回读、外部依赖、长时任务、失败恢复或破坏性操作尚未完成闭环。

每一行按以下五层记录：

1. **页面可达**：入口、路由、权限边界和空态是否可理解。
2. **控件可操作**：输入、筛选、tabs、弹窗、按钮和返回路径是否能实际使用。
3. **反馈可见**：加载、成功、失败、禁用、确认和进行中状态是否清楚。
4. **结果可回读**：刷新、返回、列表或详情是否能看到状态 / 数据变化。
5. **失败可恢复**：是否有重试、取消、关闭、返回或不丢失上下文的动作。

### 已真实体验与尚未完成的边界

本轮确实真实点击并观察了以下关键 UI 状态：知识卡片提炼中的加载态、成功预览和取消回退；雷达正文未生成 / 重抓 / 审核状态；AI 讨论回答与引用；研究编辑器的预览、AI 助手、版本历史、删除确认和发布禁用态；Admin 批量选择、原生确认提示、研究归档确认；搜索结果和类型切换；专题 tabs、筛选和加载更多；全局浅色 / 深色主题切换。

## 验收指标

- AI 调研结果移动端默认不出现正文内部滚动；非必要独立滚动容器显著减少。
- 主要移动端操作的实际触控热区达到 `44×44px`，相邻目标间距至少 `8px`。
- Admin 移动端用户无需猜测即可发现表格可以横向查看。
- 关键路由发生错误时，用户可以重试或返回，不会停留在无恢复路径的错误页。
- AI 调研结果用户在 5 秒内能回答“能不能用”和“下一步是什么”。
- 主要页面继续保持无根页面横向溢出。
