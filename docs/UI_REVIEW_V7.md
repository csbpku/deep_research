# 技术调研平台 UI Review & Mockup v7

## 结论

有必要做一次完整的视觉重构，但建议先停留在 mockup 验证阶段，再进入真实 Next.js 组件改造。当前问题不是单一字体或主色，而是所有页面都使用相近的浅灰底、细边框和圆角卡片，信息层级被压平，内容研究产品看起来像同一套后台表单的不同排列。

v7 将产品定位为“面向小型技术团队的研究工作台”：首页负责决定今天先看什么，雷达负责发现和排序，日报负责编辑式沉淀，详情负责阅读和证据，AI 调研负责运行，编辑器负责写作，Admin 负责处理队列与健康状态。

## 实施状态（2026-08-05）

v7 mockup 方向已确认，并已迁移到真实 Next.js 页面。当前迁移覆盖 Shell、首页、技术雷达、热点主题、雷达详情、日报、AI 调研、调研详情、编辑器、搜索、调研库和 Admin；保留原有路由、API、数据模型、权限边界和轮询/保存/发布行为。

雷达详情的“打开讨论 / 与 AI 讨论”共用右侧抽屉：桌面端保留正文可见区域，团队讨论和 AI 讨论均显示可展开的正文摘录，移动端使用全屏抽屉；AI 会话仍复用原有创建、历史、发送、加载和错误逻辑。评分详情、打开原文、空状态、未授权状态和错误状态也已纳入页面迁移。

## 评审范围与证据

本轮在本地开发环境以 1280×720 复核了首页、技术雷达、AI 雷达日报、调研库、AI 调研、搜索、新建调研和雷达详情页面，并检查了未登录时的受保护页面边界。已登录的调研库详情、编辑器、收藏、评论和 Admin 也已走通；“加载失败 / 需要登录”在真实页面中区分为准确的登录状态。

Readwise Reader、Feedly、Notion、Linear 和 GitHub 的内容仅作为模式参考：阅读队列与来源沉淀、安静表面层级、状态和筛选、命令入口及高密度操作。v7 不复制它们的品牌或布局。

## 根因归因

### 字体与层级

现有系统字体本身可读，主要问题是层级档位过少，以及大量 10–11px 灰色元数据。v7 保留中文友好的系统字体栈，定义页面标题、内容标题、正文、元数据四档；日期、分数、状态编号使用等宽字体。真实改造时应避免把所有辅助信息都压成小灰字。

### 颜色与对比度

页面底色、卡片底色和弱化区域过于接近，边界依赖细线。v7 固定三层表面：浅色 `#F4F4F1 / #FFFFFF / #EAEAE4`，研究蓝 `#315FE8` 只用于主操作、当前项、链接和关键状态；语义色固定为成功 `#2F7A5A`、注意 `#A2711A`、错误 `#A84438`。暗色主题使用深灰蓝画布、略亮内容表面和低饱和语义色。真实实现需再次用对比度检查长文、标签和禁用态。

### 间距与密度

首页留白过多，雷达和 AI 调研同时存在拥挤与层级不明。统一按钮高度、圆角、间距和内容最大宽度；首页提高“今天先看什么”的密度，详情页放宽正文行长，Admin 使用更紧凑的表格密度。

### 边框与卡片

“每个区域一张卡”造成视觉扁平。真实改造应优先使用页面底色、内容表面和弱化表面的层级，只有跨区域、可操作或需要证据边界的内容才保留边框。详情正文不应被拆成很多同规格卡片。

### 导航与操作层级

导航需要表达工作上下文而非单纯路由列表。首页动作只保留“提交 AI 调研”和“新建调研”，且两个按钮尺寸一致；“导入资料”作为新建流程中的选择，不再与首页主动作竞争。主操作使用研究蓝，次操作使用中性按钮。

### 空、错误和未授权状态

加载失败、网络错误和未登录目前容易混为一谈。真实组件应至少区分：空数据（给出下一步）、加载失败（重试与错误原因）、未授权（登录入口）、权限不足（联系管理员）。日报降级生成也应进入统一状态带，而不是隐藏在元数据中。

## 优先级与实施建议

- **P0**：未授权/错误状态语义；详情阅读画布的可读性；主操作的清晰层级。这些直接影响理解和任务完成率。
- **P1**：统一视觉 token；首页工作台、雷达排序流、日报编辑式结构、AI 调研 brief/pipeline、编辑器写作模式、搜索和调研库列表。这是本次 v7 的主要改造面。
- **P2**：Admin 密度、更多键盘命令、收藏/评论的细节、动效和个性化视图。应在核心阅读与研究流程稳定后处理。

建议顺序：先确认 mockup 方向；再抽取共享 token、Shell、按钮/状态/空状态组件；随后逐页迁移首页、雷达、日报和详情；最后迁移 AI 调研、编辑器、搜索、调研库和 Admin。保留现有路由、数据模型、权限边界和真实业务功能。
