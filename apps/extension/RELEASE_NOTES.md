# Reader 更新日志

记录 Reader 扩展每个版本的用户可见变更、对应提交范围和商店提交状态。

版本号以 `apps/extension/package.json`、`apps/extension/manifest.json` 和
`apps/extension/wxt.config.ts` 三处为准，必须一致。CI 在扩展源码变化但版本号
未提升时会拒绝发布，因此每一批功能都要先在这里落一条记录再提商店审核。

## 发布批次策略

商店审核是逐个版本的固定成本，因此不逐个小功能提交。做法是：功能合入
`main` 后先记在本文件，等攒够一批有用户价值的变更再提升版本号、打商店包并
提交审核。合入 `main` 只影响平台和 Beta Release，不影响已安装的商店版本。

## 0.2.32

状态：开发完成后待发布；未提交 Chrome Web Store 审核。

- 窄侧栏：模型与阅读范围分行显示，避免英文选段状态下模型名被挤没。
- 阅读面板：细化原文标题层级、选段操作的图标间距与关闭按钮，优化空状态文字换行。
- 设置与历史：简化设置标题层级，统一状态标签对齐、历史计数和清除搜索图标。
- 英文界面：补齐本页保存内容的标题翻译。
- 收藏：完整列表新增关键词搜索、类型筛选、总数和分页，不再仅显示每类最近 12 条；关键词覆盖原文、笔记、AI 结论、标签与来源地址。
- 删除：收藏删除前显示条目确认，删除后可在当前面板关闭前逐次撤销；已在其他页面恢复的内容不会被旧快照覆盖。
- 总结：首问按钮随阅读范围显示“文章讲了什么？”或“这段讲了什么？”，图示范围下隐藏文字总结入口。
- 首次配置：模型连接与保存步骤提前，语言偏好后移，平台数据使用细节按需展开。

## 0.2.29

状态：已合入 `main`（`d2ea516`），已发布 Beta 0.2.29，待提交商店审核

包含两批功能：

- 联网搜索（PR #12）：阅读聊天新增可选的联网检索开关。默认关闭，打开后可让模型
  检索当前原文之外的信息，回答仍标注哪些内容来自原文、哪些来自检索结果。
- 翻译提速（PR #13）：
  - 长文首批缩小以提前显示，后续批次按最多 24 块、约 3,000 字符处理，减少往返次数。
  - 平台翻译请求并发从 3 提升到 6，与 Web BFF 上限和 AI engine 的 LLM 信号量对齐。
  - 引擎侧可重试的供应商失败（429/529/超时）先等待抖动指数退避再重试。
  - 独立模式沿用平台对 MiniMax M3.1 的低推理档策略，翻译延迟明显下降。
  - 平台模式不再因为单个批次缺项就重译整段，只补译缺失或冲突的块。

生产链路实测（部署后，交错重复两轮）：287 块、41,215 字符的文章，
翻译墙钟从约 119 秒降到约 50 秒，覆盖 287/287，无未翻译块、零失败。
